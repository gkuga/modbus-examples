# power-meter

架空の電力計を Modbus TCP サーバとして動かし、**レジスタマップを見ながら生の値を解釈する** 練習をするサンプル。

想定: 太陽光パネル付きの家の分電盤にある電力計。家の消費が発電を上回ると買電 (電力がプラス)、
下回ると売電 (電力がマイナス)。負荷はリレーで ON/OFF できる。

## 実行

```sh
make install
make run-server   # ターミナル 1
make run-client   # ターミナル 2 (何度実行してもよい)
```

サーバ側には送受信したフレームが hex で表示される。

## レジスタマップ

これがメーカーのマニュアルに載っている想定の表。**クライアントはこの表を知らないと値の意味が分からない。**
通信条件や機器の動作まで含めた仕様書の形にしたものは [SPEC.md](SPEC.md) にある。

アドレスは PDU 上のアドレス (0 始まり)。「番号表記」は慣習的な 1 始まりの表記で、先頭の桁がテーブルを表す。

### Coils (1 bit, 読み書き / FC 0x01 読み, 0x05・0x0F 書き)

| アドレス | 番号表記 | 名称 | 値 |
| --- | --- | --- | --- |
| 0 | 00001 | 負荷リレー | 1 = ON, 0 = OFF |

### Discrete Inputs (1 bit, 読み取り専用 / FC 0x02)

| アドレス | 番号表記 | 名称 | 値 |
| --- | --- | --- | --- |
| 0 | 10001 | 電力超過アラーム | 1 = 有効電力がしきい値 (40001) を超えている |

### Input Registers (16 bit, 読み取り専用 / FC 0x04) — 計測値

| アドレス | 番号表記 | 名称 | 型 | 単位・倍率 |
| --- | --- | --- | --- | --- |
| 0 | 30001 | 電圧 | UINT16 | 0.1 V |
| 1 | 30002 | 電流 | UINT16 | 0.01 A |
| 2 | 30003 | 有効電力 | **INT16** | 1 W (マイナス = 売電) |
| 3 | 30004 | 力率 | UINT16 | 0.001 |
| 4-5 | 30005-30006 | 周波数 | **FLOAT32** (上位ワードが先) | Hz |
| 6-7 | 30007-30008 | 積算電力量 (買電) | **UINT32 (下位ワードが先)** | 1 Wh |

### Holding Registers (16 bit, 読み書き / FC 0x03 読み, 0x06・0x10 書き) — 設定

| アドレス | 番号表記 | 名称 | 型 | 内容 |
| --- | --- | --- | --- | --- |
| 0 | 40001 | アラームしきい値 | UINT16 | 1 W, 初期値 1000 |
| 1 | 40002 | 積算電力量リセット | UINT16 | 1 を書くと積算電力量を 0 にする (読むと常に 0) |

マップにないアドレス (例: Input Register 8) を読むと例外レスポンス (例外コード 0x02 Illegal Data Address) が返る。

## 出力例と読み方

```
1. Read measurements (input registers, function code 0x04)
  raw input registers 0-7:
    [0]= 1015 (0x03f7)  [1]=  273 (0x0111)  [2]=65263 (0xfeef)  [3]=  986 (0x03da)
    [4]=16968 (0x4248)  [5]= 4590 (0x11ee)  [6]=57920 (0xe240)  [7]=    1 (0x0001)
  decoded:
    30001     voltage      UINT16 x0.1   -> 101.5 V
    30002     current      UINT16 x0.01  -> 2.73 A
    30003     power        INT16         -> -273 W  (as UINT16 it would be 65263)
    30004     power factor UINT16 x0.001 -> 0.986
    30005-06  frequency    FLOAT32       -> 50.02 Hz
    30007-08  energy       UINT32 (low word first) -> 123456 Wh  (wrong word order would give 3795845121)
```

通信で届くのは `raw` の 16 bit の数値の列だけ。`decoded` はクライアントがマップを見て解釈した結果。

### 倍率 (30001, 30002, 30004)

Modbus のレジスタは整数しか入らないので、小数は倍率を掛けて整数にする。
電圧 `1015` は「0.1 V 単位」と決まっているから 101.5 V。マップを見ずに 1015 V と読むと大事故になる。

### 符号付き (30003)

`65263` (0xfeef) は UINT16 として読めば 65263 だが、INT16 (2 の補数) として読むと -273。
レジスタ自体には符号の情報がなく、どちらで読むかはマップで決まる。
最上位ビットが 1 (0x8000 以上) なら負、というのが 2 の補数のルール (`client.py` の `to_int16`)。

### 32 bit の値 (30005-30008)

1 レジスタは 16 bit (0〜65535) なので、それを超える値はレジスタ 2 個を使う。
積算電力量 123456 Wh は 65535 を超えるので 2 個必要。

```
123456 = 0x0001_e240
         ^^^^ ^^^^
         上位  下位
```

この電力計は **下位ワードを先に** 送る (`[6]=0xe240, [7]=0x0001`)。
逆に解釈すると `0xe240_0001` = 3795845121 になってしまう。
ワードオーダーは機器によって違い、規格は決めていない。マップに書いていなければ実機で確かめるしかない。

周波数の FLOAT32 は IEEE 754 の 32 bit をレジスタ 2 個に分けたもの (こちらは上位ワードが先)。
`0x4248_11ee` を float として読むと 50.02。

pymodbus には変換ヘルパーもある (`client.py` は仕組みが見えるように手で変換している):

```python
client.convert_from_registers(regs[6:8], client.DATATYPE.UINT32, word_order="little")
client.convert_from_registers(regs[4:6], client.DATATYPE.FLOAT32)
```

### 書き込みと機器の振る舞い (手順 3〜5)

- 40001 (しきい値) を 0 にすると、買電中ならアラーム 10001 が立つ
- コイル 00001 (リレー) を OFF にすると負荷がなくなり、電力がマイナス (売電のみ) になる

レジスタへの書き込みが「設定の変更」や「機器の操作」になる。何が起きるかはやはりマップ次第。

## 試してみること

- `make run-client` を何度か実行する → 積算電力量が増えていく (サーバは時間を 60 倍速で進めている)
- 積算電力量をリセットする → 上位ワードが 0 になり、1 レジスタに収まる値に戻る
  ```sh
  uv run python -c "from pymodbus.client import ModbusTcpClient as C; c=C('127.0.0.1', port=5020); c.connect(); c.write_register(1, 1)"
  ```
- `client.py` の `to_uint32(high=regs[7], low=regs[6])` を逆にしてみる → 値がでたらめになる
- 範囲外 (Input Register 8 など) を読んでみる → 例外コード 0x02
- 読み取り専用の Input Register に書こうとしてみる → そもそも書き込み用のファンクションコードが存在しない
